# Production contract

The user explicitly accepted `assets/reference/panna-approved.gif` on 2026-11-08 as the final reference effect. It is a quality benchmark for short illustrated-character GIFs, not a required character, framing, resolution or motion for every project. The reference is 2s,252 square,50 encoded image states derived from24 drawn keys plus26 inferred transitions. Do not equate those counts with visual quality or promise a new action will work without inspection.

Success means recognizable identity and acting, a stable stationary background, stable idle clothing, coherent anatomy/props, single clean facial contours, natural expression/action transitions, and an intentional start/end or loop. Preserve a user's accepted stage while changing one demonstrated defect. No blanket approval of later outputs or release/publishing is implied.

Before production, record the identity reference, intent/action, entry/exit poses, camera/axis, moving versus idle regions, duration, loop behavior and output detail. Make a single short action for inspection before expanding a film. Do not freeze an intentionally moving torso or rely on interpolation to invent large occluded actions.

## Stage ownership

- Art creation, new poses and raster repairs: native imagegen. Save exact prompts, input roles, output path and actual media type. A static sequence sheet is not native GIF generation.
- Extraction, alpha-layer compositing, motion-texture stabilization, temporal interpolation, encoding and artifact checks: the local helper. It does not generate art or automatically locate eyes/neck.
- Interpretation and visual judgment: the agent, then user feedback where requested. Mechanical checks cannot establish natural acting, source correctness or artistic acceptance.

The helper defaults to a simple sheet extraction and GIF encode. Enable matte repair, idle-torso stabilization or inferred transitions only when the action and inspected inputs justify them. The bundled Panna recipe is deliberately specific to that chest-up view.

## Review against the reference

View the actual approved GIF and the actual new GIF at native size. Inspect extracted keys and final decoded frame sheets separately. Use enlarged eye/mouth/neck samples for changing or newly occluded features and both sides of the loop. Reject double pupils/lips, fragmented hair/neck edges, prop flips, unexplained background motion and palette flashes. Subtle texture/line variation must be assessed as an actual visual limitation rather than excused by passing statistics.

Record distinct statuses for complete decode, source/key/static checks, frame-level visual review, normal-speed playback and user acceptance. No automatic `approved` flag is issued. If playback cannot be observed, record `unavailable`; user-confirmed historical reference approval does not certify a new output.

The CLI writes SHA-bound reports and takes SHA-bound review records. `finalize` requires completed frame/content review, artifact evidence and either observed playback or explicitly documented user acceptance of the exact artifact. An agent can perform the review without asking the user for permission; a missing playback surface may leave a clearly labeled preview for user viewing. A review record attests to judgment, not a detector success.

## Delivery

Show the selected GIF inline, link its project/checks, state concrete changes and material limits, and preserve older versions/rejected trials separately. GIF is the single-shot review/result asset; PNG keys, alpha masks, recipe, prompts and receipts are the editing sources. Do not upscale and claim extra detail. No remote API, third-party installation, uploads, publishing or unattended new work is part of this skill.
